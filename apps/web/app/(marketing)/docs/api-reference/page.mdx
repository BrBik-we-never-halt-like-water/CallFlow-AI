# API reference

Everything the dashboard does, it does over this API. Base URL is your deployment's
host; all bodies are JSON.

Authenticate with a **Voice API key** from **Settings → API keys**. Keys are shown once
at creation and stored hashed, so if you lose one, revoke it and make another.

## Endpoints

| Endpoint | Purpose |
|---|---|
| `GET /api/health` | Service status and the deployment's default safety settings. |
| `GET /api/v1/voice-agents` | List the agents this organisation has built. |
| `POST /api/v1/voice-agents` | Create an agent — its voice, its model, its prompt, and the fields it must collect. |
| `PATCH /api/v1/voice-agents/{id}` | Update an agent. The body is the full agent, not a partial patch. |
| `DELETE /api/v1/voice-agents/{id}` | Remove an agent. You can delete the ones you created; an owner or admin can delete any. |
| `GET /api/v1/telephony/numbers` | List the numbers this organisation holds, masked. |
| `POST /api/v1/telephony/numbers/sync?provider=…` | Ask the carrier what the account actually holds, and record it. |
| `PATCH /api/v1/telephony/numbers/{number_id}` | Retire a number, or bring a retired one back. |
| `POST /api/v1/runs` | Start a run. Every run dials for real. Returns immediately; the run proceeds in the background. |
| `GET /api/v1/runs` | List runs for the active organisation. |
| `GET /api/v1/runs/{id}` | Poll status, outcomes, and stats. |

An agent and a number are separate things on purpose. The agent is how the call
sounds and what it collects; the number is which line it goes out on. That is what
lets one agent dial through any carrier you have connected.

## Health

Unauthenticated, so it reports the deployment's own defaults rather than your
organisation's live usage or overrides. `GET /api/v1/safety`, signed in, is where your
own effective settings and today's usage live.

```json
{
  "ok": true,
  "calling_available": false,
  "max_calls_per_run": 3,
  "allowlist_active": true,
  "limits": { "daily_budget": 25, "per_window": 2, "window_minutes": 60 }
}
```

`calling_available` is the one to check before automating anything. While it is
`false`, no run on this deployment can place a call, whatever else is configured.

## Numbers

A number belongs to the organisation, not to an agent. `GET` reads CallFlow's own
records and never calls the carrier — a picker must not depend on a vendor being
reachable — so `POST /numbers/sync` is what refreshes them from the account.

```json
[
  {
    "id": "9f1c…",
    "provider": "twilio",
    "phone_masked": "+1*******100",
    "label": "Mumbai sales",
    "status": "verified",
    "diallable": true,
    "last_error": null,
    "last_synced_at": "2026-08-14T09:02:11Z"
  }
]
```

Numbers are masked in every response, the same as everywhere else. `diallable` is the
field to read when building a picker: it is the domain's own rule about whether a run
may dial from that line, not a status string you have to keep in step.

Syncing is idempotent, so pressing it twice is a no-op rather than a second set of
rows. A number that has since disappeared from the carrier is marked `disabled`, never
deleted — it may have placed real calls.

## Starting a run

A run binds one agent to one or more of your numbers and a list of contacts. Every run
dials for real as soon as it starts — there is no simulated mode. The allowlist,
per-run ceiling, rate limit, daily budget, and suppression list are all checked before
each call goes out, and any of them can stop a contact from being dialled.

```json
{
  "voice_agent_id": "3ab2…",
  "number_ids": ["9f1c…", "d40e…"],
  "contacts": [
    {
      "name": "Aditi",
      "phone": "+15555550100",
      "context": { "destination": "Bali", "detail": "asked about December" }
    }
  ],
  "name": "December enquiries",
  "run_instruction": "Mention the December promotion if they ask about price.",
  "allocation_strategy": "round_robin"
}
```

| Field | Required | What it does |
|---|---|---|
| `voice_agent_id` | yes | Which agent makes the calls. Its prompt and its collect fields drive every call in the run. |
| `number_ids` | yes | Which of your lines the run may dial from. A run with none is refused. |
| `contacts` | yes | Each needs a `name` and an E.164 `phone`. `region`, `language`, and a free-form `context` object are optional. |
| `name` | no | A label for the run list. Runs are also identifiable by their agent and start time. |
| `run_instruction` | no | Appended to every prompt in this run, so a one-off instruction does not mean editing an agent the whole organisation shares. |
| `allocation_strategy` | no | How contacts are spread across `number_ids`. Defaults to `round_robin`. |

Each contact's `context` is where per-contact detail goes, and its keys reach that one
contact's prompt — see [Writing a good goal](/docs/writing-a-good-goal).

Response:

```json
{ "run_id": "run_8f2a1c", "total": 1 }
```

Contacts that would collide on one result row are collapsed before the run starts, so
a list containing the same person twice dials them once and `total` reflects that.

## Polling a run

`GET /api/v1/runs/{id}` returns the run with every outcome recorded so far, plus stats.

A row appears as soon as a call is placed, so an in-flight call is visible while it
happens. `stats.completed` counts only calls that have actually resolved — an
in-flight one is not progress yet, and counting it as progress is how a progress
indicator ends up going backwards.

Poll every two to three seconds. There is no long-polling; if you want push instead,
use [webhooks](/docs/webhooks).

## Errors

Errors come back with a `detail` string written for a person, not a code to look up.

| Status | Meaning |
|---|---|
| `400` | The request was understood and rejected. `detail` says what to change. |
| `404` | No agent, number, or run with that id. |
| `409` | A number status change that the state machine does not allow. `detail` names both ends. |
| `429` | A rate limit or the daily budget. Honour `Retry-After`. |
| `502` | The carrier answered a sync with an error. `detail` is the carrier's own message. |

A `400` on a run is usually one of four things: no contacts, no diallable number among
the `number_ids`, an unknown `voice_agent_id`, or a number that is not E.164.
