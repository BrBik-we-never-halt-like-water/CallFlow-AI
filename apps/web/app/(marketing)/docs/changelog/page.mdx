# Changelog

Newest first. Dates are the day a change reached production.

## 2026-08-18 — Voice agents replace campaigns

A campaign bundled the goal, the fields, and the line to dial from into one object. Those
are three different decisions with three different lifetimes, so they are three things
now.

- **Campaigns are gone,** replaced by **voice agents**. An agent holds how a call sounds
  and thinks — a transcription provider, a voice, a model, a system prompt, and the
  fields it must collect. It is shared across the organisation and reused by every run.
- **Numbers belong to the organisation, not to an agent.** Connect a carrier in
  Integrations and sync what the account holds; a run then picks which lines it may dial
  from. One agent can dial through any carrier you have connected.
- **A run binds an agent to numbers and contacts.** `POST /api/v1/runs` takes a
  `voice_agent_id` and `number_ids` in place of a `campaign_id`, plus an optional
  `run_instruction` appended to every prompt in that run only — so a one-off note does
  not mean editing an agent the whole organisation shares.
- **Any spreadsheet column is now per-contact context.** A `destination` column reaches
  that one contact's prompt, so one agent opens with Bali for the first enquiry and
  Singapore for the third.
- **A required field that never got answered escalates.** A call that connected, ran to
  completion, and still ended without a field you marked required is routed to a person
  with the missing fields named, rather than counted as closed.
- **The `/api/v1/campaigns` endpoints are removed,** including the goal preview. Agents
  live at `/api/v1/voice-agents` and numbers at `/api/v1/telephony/numbers`.

## 2026-08-07 — Dry run removed, runs are persisted

Every run now dials for real from the first one — there is no longer a simulated mode.

- **Dry run is gone.** The switch, the confirmation dialog, and the simulated lamp
  state are removed from the product. The guards that were already real — the
  allowlist, the per-run ceiling, rate limiting, the daily budget, and calling
  windows — are unchanged and are what protects you now.
- **The suppression list is enforced in the dial path,** not just shown in the
  interface. An opted-out number is rejected before a call is ever placed, on every
  run.
- **Campaigns and runs are persisted per organisation,** in place of the in-memory
  store used until now. Nothing is lost on a restart or a deploy.

## 2026-08-05 — Interface rebuild

The whole interface was rebuilt around one idea: a completed call tells you nothing, so
the state of every call should be visible the moment it ends.

- **Lamp strips replace progress bars.** A run now shows one lamp per call, and each
  lamp carries a state — queued, simulated, in conversation, queued for retry,
  auto-closed, or needs a person. A bar told you how much was done; a strip tells you
  how it went.
- **The dry-run switch confirms before going live.** It is the only switch in the
  product that asks, and the confirmation shows the contact count, the credit estimate,
  the calling window, and whether the allowlist is on.
- **Safety guards are visible where you start a run,** as mono chips. A guard that is
  off renders in flare with the word `OFF`.
- **Needs a person is a worklist,** sorted oldest first, with the escalation reason
  shown as a chain read from typed fields rather than from prose.
- **Phone masking moved into one module.** A new screen can no longer ship without it.
- **Two surface modes.** Paper for the marketing site, Panel for the dashboard, both
  available everywhere and switchable.
- **New pages:** pricing with a full comparison matrix, four solution pages showing
  their goal template and result schema in full, a trust page, and these docs.
- **Accessibility:** full keyboard operation, real table semantics with `aria-sort`,
  debounced live-region announcements for run progress, and visible focus everywhere.

## Earlier

- Sampled outcomes in dry run, and live call progress in the dashboard.
- Rate limiting per window, with a shared daily budget and an owner-key bypass for
  testing.
- CSV import with per-row validation and inline errors.
- User-created campaigns with custom extraction fields.
- Sentiment triage: opt-outs and frustration escalate, bad timing is queued for retry.
- Dry-run mode, the allowlist, and the per-run ceiling.
